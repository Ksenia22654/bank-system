# Система автоматизации работы банка с физическими лицами

Курсовой проект. Веб-приложение на Java по архитектуре № 2: MVC на Servlet и JSP, СУБД Java DB (Apache Derby), контейнер Tomcat.

## Запуск

Нужна только JDK 8 или новее. Tomcat и библиотеки лежат в проекте, СУБД отдельно устанавливать не нужно, среда разработки не требуется.

1. `run.bat` — запускает сервер; при первом запуске собирает приложение и создаёт базу данных из SQL-скрипта.
2. Откройте в браузере <http://localhost:8080/bank/>.
3. `stop.bat` — останавливает сервер.

Прочие команды:

- `build.bat` — пересобирает приложение после изменения исходного кода; при работающем сервере откажется и попросит сначала выполнить `stop.bat`;
- `init_db.bat` — создаёт базу данных из `sql/create_db.sql` утилитой СУБД, без запуска приложения.

Чтобы вернуть начальные данные, остановите сервер и удалите папку `data`.

Сквозной тест `tests/e2e.mjs` (нужен Node.js, команда `node tests/e2e.mjs`) проверяет работающее приложение на начальных данных и меняет их, поэтому после него данные стоит сбросить.

Настройки меняются без правки кода: порт — в `tomcat/conf/server.xml`, каталог данных, подключение к БД и ставка по кредитам — в `conf/bank.properties`.

## Возможности

- **Клиенты:** поиск, добавление, редактирование, удаление, карточка клиента.
- **Счета:** открытие в разных валютах, выписка, закрытие, удаление.
- **Операции:** пополнение, снятие, перевод с конвертацией по курсу, начисление процентов, журнал за период.
- **Кредиты:** заявка, изменение условий, одобрение или отказ, аннуитетный платёж, автоматическое закрытие при погашении.
- **Справочники и пользователи:** валюты, виды счетов, учётные записи с ролями и блокировкой.
- **Аналитика:** показатели и диаграммы, у каждой есть вид таблицей.
- **Отчёты:** клиенты, счета, операции, кредиты и выписка сохраняются в текстовый файл.
- **Резервные копии:** сохранение данных на сервере в любой момент и загрузка ранее сохранённых.

## База данных

Скрипт `sql/create_db.sql` создаёт 10 связанных таблиц:

| Таблица | Назначение | Внешние ключи |
|---|---|---|
| `roles` | роли | — |
| `operation_types` | виды операций | — |
| `loan_statuses` | статусы кредитов | — |
| `currencies` | валюты и курсы | — |
| `account_types` | виды счетов и ставки | — |
| `clients` | физические лица | — |
| `users` | учётные записи | `roles`, `clients` |
| `accounts` | счета | `clients`, `account_types`, `currencies` |
| `loans` | кредиты | `accounts`, `loan_statuses` |
| `operations` | журнал операций | `operation_types`, `accounts` (два ключа), `loans`, `users` |

Приведение к 3НФ:

- **1НФ:** все значения атомарны, повторяющихся групп нет: ФИО разбито на три поля, а валюта и вид счёта вынесены в справочники.
- **2НФ:** первичные ключи всех таблиц простые, поэтому зависимости от части ключа невозможны.
- **3НФ:** транзитивных зависимостей нет. Например, в `accounts` хранится `currency_id`, но не код и не курс валюты; в `loans` хранится только `account_id`, а клиент и валюта определяются через счёт; название статуса или вида операции хранится только в справочнике. Ежемесячный платёж и остаток долга не хранятся, а вычисляются.

Поле `accounts.balance` — итог по журналу операций. Его не вычисляют при каждом запросе, потому что по нему выполняется атомарное условное списание: `UPDATE ... WHERE balance >= ?`. Это денормализация ради производительности и защиты от перерасхода, а не нарушение 3НФ: поле зависит только от ключа счёта.

## Бизнес-логика

- **Перевод** (`OperationService.transfer`): одна транзакция; счета обновляются в порядке возрастания идентификаторов, чтобы встречные переводы не блокировали друг друга; сумма зачисления = сумма × курс списания / курс зачисления.
- **Списание** (`AccountDao.debit`): условие `balance >= сумма` проверяется в самом `UPDATE`, поэтому параллельные запросы не уведут счёт в минус.
- **Аннуитетный платёж** (`Loan.annuityPayment`): A = S × i / (1 − (1 + i)^(−n)), где i — месячная ставка, n — срок в месяцах.
- **Проценты** (`OperationService.accrueInterest`): остаток × годовая ставка / 100 / 12, не более одного раза в месяц на счёт.
- **Восстановление копии** (`BackupService.restore`): все таблицы заменяются в одной транзакции; при ошибке данные остаются прежними.

## Версии

Tomcat 9 совместим с Servlet 3 и JSP 2.2 и использует пакет `javax.servlet`, которого требует задание. Браузер — любой современный, поддерживающий ECMAScript 2021.
